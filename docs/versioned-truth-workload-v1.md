# Versioned-truth workload v1 (deterministic, synthetic)

The executable fixture `bench/fixtures/versioned_truth_workload_v1.json` replays 28 cases across four four-turn corrections (16 as-of/current queries), six multi-owner votes (including clone floods, deadlocks, honest majority and unanimity), and six exchanged artifacts (valid, content/owner/provenance tampered, and intact-but-weaponized content). Run `PYTHONPATH=. python bench/versioned_truth_workload.py --output bench/results/versioned_truth_workload_v1.json` from the repository root. The pinned seed is provenance only: cases are explicit, not randomly sampled. The output records the fixture's SHA256, each expected/actual result, both stores' verdicts, and control status.

**Observed v1 result:** 28/28 NEURAL_MESH correct, 20/28 append-only flat control correct; all 28 per-case control checks passed. By pillar: temporal 16/16 vs 16/16 (tie); consensus 6/6 vs 2/6; exchange 6/6 vs 2/6. The flat baseline receives identical event/vote/payload inputs but uses timestamp scan for as-of truth, raw-event majority with latest-event tie-break for votes, and accepts every transferred payload without integrity/safety checks. This is a *specified naive policy*, not a claim that flat or append-only data cannot implement owner weighting or validation. Indeed, an append-only timestamped log answers all as-of queries here. The older `bench/versioned_truth_bench.py` latest-value-only baseline cannot do that and must not be generalized to all flat systems.

The mesh replays corrections through supersede chains with pinned logical `valid_to`, resolves as-of windows with `resolve_at` and checks `history`; uses `reach_consensus` with distinct owner identities; and imports via `import_artifact`, which verifies hash then uses `ContentValidator` and leaves rejected artifacts unpersisted. The artifact hash is self-consistency/tamper evidence, **not an authenticated signature**: an attacker who controls the payload can rehash a changed claim. The intact-poison case here means *intact hash with malicious content*, not a cryptographic signature. An owner value supplied by an attacker is not independently authenticated by this benchmark. Owner authentication and unauthorized-but-self-consistent claims remain separate security gates.

**Scope:** fixed small synthetic workloads, not sampled users, production traffic, latency, judge quality, a LongMemEval leaderboard score or a security proof. Source package and production version are reported separately. Rerun `PYTHONPATH=. python -W error::ResourceWarning -m unittest tests.test_versioned_truth_workload -v` and independently parse the JSON; require 28 unique case IDs, zero failed cases/controls and the exact fixture hash before citing. Do not conflate 28/28 structural behavior with end-to-end answer accuracy.
